# Spec 0005 — Audit: access hardening, smarter AI, learner engagement, insights

**Status:** all four phases done, green; post-audit fixes applied (§5). **Started:** 2026-09-24. **Build log:** [HANDOFF.md](HANDOFF.md).

## Why

On 2026-09-24 the user asked for a full audit of the codebase (AI coverage, configurability, roles and permissions), followed by building the missing features "one by one in order". Three read-only audits ran first; this spec records what they found and the order agreed with the user.

**Design rule for this spec (user decision, 2026-09-24):** screens and UI with no client mockup may be built, but they **must reuse the existing design system and UI/UX exactly**: the locked shell, `PageHeader`, `PanelCard`, `StatCard`, `StatusPill`, `IconChip`, the `@theme` tokens, and the spacing and card recipe of the nearest built sibling screen. No new visual language. This narrows AGENTS.md §0.5's "ask for the mockup first" for the screens listed below only.

## Phases (in the order the user approved)

| #   | Phase                      | Scope                                                                                                                                                                                          |
| --- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Access hardening           | Fix the leaks the roles audit found, each with a negative test (§1)                                                                                                                            |
| 2   | Smarter role-play AI       | Learner level from the Pre-test into prompts; turn awareness + server-enforced `max_turns`; Anthropic provider parity + prompt caching; deterministic scoring; admin score override + re-grade |

## §2 Smarter role-play AI (phase 2) — what changed and why

| §   | Change                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Why / requirement                                                                                              |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 2.1 | **Learner level.** `users.english_level` + `english_level_assessed_at` (`App\Enums\EnglishLevel`: beginner / elementary / intermediate, the same bands as `ScenarioDifficulty`). Set by `TestScorer::finish` from the sitting's auto-graded percentage; the latest Pre- or Post-test wins. Thresholds in `config('guesvia.levels.thresholds')` (`LEVEL_ELEMENTARY_FROM`=40, `LEVEL_INTERMEDIATE_FROM`=70). The level pitches the role-play guest and the practice evaluators; Pre- and Post-test answers are judged on the fixed scale (§5.2)                                                                                                                                                                                 | The prompt used to assume "a low English level" for everyone. Difficulty tags, not CEFR (open question 8.1 #6) |
| 2.2 | **Pacing and a hard turn bound.** `RoleplayPrompt::pacingLine` tells the guest where the conversation stands (opening / too early / may close / wrap up / final line). `RoleplayService::message` refuses a turn past `max_turns` and ends the conversation instead; the chat shows "Reply N of M" and, at the limit, a "Get my feedback" panel                                                                                                                                                                                                                                                                                                                                                                               | `max_turns` was never enforced and the model was never told the turn number (RP-04, RP-05)                     |
| 2.3 | **One prompt for every provider.** `RoleplayPrompt::replySystem` / `evaluationSystem` / `forVoice` plus `Concerns\BuildsRoleplayPrompts` (message mapping, evaluation parsing) and writing/speaking prompts in `Concerns\BuildsAssessmentPrompts`. The Anthropic provider now sends the admin's instruction and guardrails, uses the fast model for learner-facing replies, caches the stable system prompt (`cache_control`; the per-turn pacing line rides in its own uncached block, §5.3), counts cached tokens in usage, sends no sampling parameters (current Claude models reject `temperature`), and retries only 408/409/429/5xx. The voice call reads the admin's model override (`AiModelSettings::fastChatModel`) | The Anthropic copy had drifted and ignored the admin's system prompt (RP-04, ADM-02, API-03, API-04)           |
| 2.4 | **Consistent scoring.** Shared scoring anchors (`RoleplayPrompt::SCORING_ANCHORS`) in every evaluator; the OpenAI-compatible provider judges at temperature 0.1 (conversation stays 0.6); the role-play and practice evaluators receive the learner's level, test answers the fixed scale, and the bar used is stored (§5.2); feedback must quote what the employee said                                                                                                                                                                                                                                                                                                                                                      | The same answer could score differently run to run (AIE-04)                                                    |
| 2.5 | **Score override and re-grade.** Permission `scores.override` (Super Admin; can be granted to a custom role, still bounded to the actor's hotel by `AttemptPolicy`/`RoleplayAttemptPolicy::overrideScore`). `App\Services\Reports\ScoreOverrides` + `Admin\Reports\ScoreOverrideController` (6 routes under `reports-export/answers                                                                                                                                                                                                                                                                                                                                                                                           | roleplay/{id}/score                                                                                            | reevaluate`). The original is kept (`attempts.original_score`, new `roleplay_attempts.original_overall_score`), with who/when/why; an auto-graded test answer moves its sitting total; re-grading keeps an override in place. Reports → Detailed Answers / AI Role-play Logs get an "Adjust" action and `ReportsScoreDialog`; the answers and role-play exports gain override columns (the reason is blank in the anonymised export) | AIE-05 existed only as columns; SEC-06 audit; REP-06/REP-07 |

## §5 Post-audit fixes (2026-09-24)

An independent review of the four phases found five real problems. All five are fixed; each carries a test.

| §   | Problem found                                                                                                                                                                                                           | Fix                                                                                                                                                                                                                                                                                                                                                                                     | Requirement              |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| 5.1 | The AI coach received Pre/Post-test percentages and the skill breakdown whatever the test's `results_visibility`, so it could tell a learner a score the admin had hidden (a research-bias risk)                        | `LearnerCoach::context` sends a sitting's percentage only when its test `showsScore()`, the skill breakdown only when it `showsBreakdown()`, and the level label (derived from the score) only with a shown score; a hidden sitting appears as `taken: true` alone. The coaching prompt is told never to estimate or mention a figure that is absent                                    | TEST-04                  |
| 5.2 | Every AI evaluator was pitched at the learner's level, and the level moves after every sitting: a Post-test answer was judged against a different bar than the Pre-test answer, and nothing recorded which bar was used | `Attempt::gradingLevel()`: lesson practice at the learner's level, a test answer (`test_attempt_id` set) on the one fixed scale (`assessmentContext(null)` now says so). New `attempts.graded_level` and `roleplay_attempts.graded_level` (migration `2026_09_24_100007`) record the bar beside every AI score; both exports gain a "Grading level" column. Role-play stays level-aware | TEST-02, TSTM-03, AIE-04 |
| 5.3 | Prompt caching on the Anthropic provider never hit: the per-turn pacing line ("replied N of M") sat inside the single cached system block, so the prefix differed every turn                                            | `RoleplayPrompt::replySystemParts()` splits the reply prompt into a stable part and the turn line; `AnthropicAiProvider::complete()` sends the stable part as the cached block and the turn line as a second block after the breakpoint. `replySystem()` (OpenAI-compatible) joins the two, unchanged                                                                                   | API-03                   |
| 5.4 | A role-play never touched `users.last_activity_at`, so a learner who only did role-plays showed a live streak while the dashboard listed them "No activity for N days" and the inactivity reminder chased them          | `RoleplayService::start` / `message` and `VoiceCallService::start` (not a preview) call `ProgressService::touch`, the same fact the streak, the at-risk list and the reminder rule read                                                                                                                                                                                                 | DATA-06, REM-03          |
| 5.5 | A phrasebook review answer was not idempotent: a retried or doubled POST moved the card two boxes                                                                                                                       | The review POST requires `version` (the card's `review_count` as served, now in the card payload as `reviewCount`); the answer is recorded only when it still matches, otherwise the current state is returned with `recorded: false`. The page sends it                                                                                                                                | PROG-04                  |

Not changed, recorded: the coach reads the learner's own sittings without `Test::forLearner` scoping (a sitting a learner took on a test that was later archived still counts as theirs; there is no cross-learner path).
